# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A dependency-free static web app (`index.html` + one stylesheet + two scripts + an SVG favicon), a Japanese→English vocabulary list with an animated stroke-order player for each kana/kanji. There is no build, package manager, linter or test suite. To run it, open `index.html` in a browser (e.g. `open index.html`); it works from `file://`, so the scripts are classic `<script>` tags, not ES modules. The only external resources are Google Fonts, Google Input Tools (kanji suggestions in the add form) and KanjiVG on jsDelivr (stroke data for kanji missing from `STROKES`).

All user-facing text is in **English** (labels, status messages, hints, aria-labels). New UI strings must be in English too. (The app was originally Catalan: internal identifiers such as the `ca` field, the note type keys `gram`/`frase`/`dibuix`/`nota` and the `diccionari-japones-*` storage keys keep their Catalan names so existing saved data still loads.)

## File layout

`index.html` holds the `<head>` (title, `favicon.svg`, Google Fonts, `css/style.css`) and the markup, then loads `js/strokes.js` and `js/app.js` in that order at the end of `<body>`:

- **CSS** (`css/style.css`): a small base reset first, then color tokens on `:root`, a dark-mode override under `@media (prefers-color-scheme: dark)` guarded by `:root:not([data-theme="light"])`, and the same values again under `:root[data-theme="dark"]`. Keep all three in sync when changing colors. The layout is a two-column grid (list + sticky player) that stacks on screens ≤860px; the notebook is one column. Below 600px the table rows turn into stacked dictionary entries (pure CSS on the same markup). The look is kawaii stationery: sakura-pink paper with a polka-dot/sakura pattern (`body::before`, tinted by `--pattern`) over a faint Mount Fuji photo (`assets/img/bg.jpg` on `body::after`, `mix-blend-mode: luminosity` so it takes each theme's hue, strength set by the `--photo` opacity token; the word list `.tablewrap` and its header are see-through, their opacity set by `--list-fill`, default 72%), plum ink, a pink accent with lavender `--primary`, rounded "sticker" panels (`--r`, `--r-sm`, a pink drop shadow), pill buttons and tabs, and a cat-eared `.seal`. Note cards get a coloured top band per type (`--card-band`). Fonts are Kiwi Maru (Japanese), Zen Maru Gothic (UI) and Mochiy Pop One (title, seal). Stroke cells are sized by a `--cols` custom property that `buildStage()` sets per word. Radii come from `--r`, `--r-sm`, `--r-cell` (stroke cells) and `--pill` (buttons, chips, tabs), so a theme can square them off.
- **Themes** (CSS Zen Garden style): one markup, one stylesheet per design. `style.css` is the base design, "Sakura"; every other theme is `css/themes/<name>.css`, linked *after* it as `link[data-skin]`, redefining the tokens and restyling the same selectors (never touch the markup or JS for a theme). Current ones: `sumi` (washi, indigo-charcoal ink, vermilion hanko), `matcha` (tea house, Shippori Mincho, tea-bowl seal), `neon` (Tokyo night, always dark, glowing tubes, DotGothic16 title) and `shinbun` "Newsprint" (halftone, black and spot red, square corners, hard offset shadows). Each file `@import`s its own Google Fonts and repeats the base's three colour blocks with the same selectors (`:root`, the dark media block, `:root[data-theme="dark"]`) so it wins by source order; keep them in sync. `neon` uses one combined block because it is dark in every mode. Every token the base sets in dark mode must be redefined, or the pink leaks through. To add a theme, drop in a file and add an `<option>` to the header's `#themeSel`; `setStyle()` in `app.js` reads the list from there, swaps the link only once the new sheet has loaded (no flash) and saves the choice in `localStorage` under `diccionari-japones-estil`. An inline script in `<head>` `document.write`s the saved theme's link before first paint and sets `html[data-style]`.
- **Markup** (`index.html`): a tab bar (`#tabs`) under the header switches between two tab panels. `#pDict` holds `section.player` (stroke stage + playback controls) and `main.book` (search, the word group chips `#wgroups`, word table `#rows`, the add form `#form` inside the modal `<dialog id="addDlg">`, JSON backup `<details>`). `#pNotes` is the notebook: `main.shelf` (search `#nQ`, the "New note" button `#nNew`, type filter chips, note cards `#notes`, its own JSON backup) and `section.composer` (the note form `#nForm`, with the drawing pad `#pad`) inside the modal `<dialog id="noteDlg">`. A footer with the KanjiVG attribution closes the page. A floating "Add word" button (`#fab`, `.fab`, fixed bottom-right on every tab) switches to the dictionary tab and opens the add form as a popup (`openForm()`, focus on `#fJp`). Both popups go through `popup(dlg, onClose)`: `showModal()` over a blurred `::backdrop`; Escape, the × (`.pclose`), Cancel and a click on the backdrop close it, and `onClose` runs on every close (`wordPop` → `cancelEdit()`, `notePop` → `resetComposer()` while editing). A half-typed new word or note is kept.
- **Script**: `js/strokes.js` declares the global `const STROKES` (stroke data only); `js/app.js` is one IIFE in strict mode that reads it. DOM lookups go through `$(id)`.

## Script architecture

- **`STROKES`** (one ~100 KB line in `js/strokes.js`): a map from character to an array of `[svgPathD, numberX, numberY]` tuples in KanjiVG's 109×109 coordinate space. It covers all kana plus a set of basic kanji. Kanji missing from it are fetched on demand by `loadMissing(w)` / `kvgFetch(ch)` from `KVG_URL` (KanjiVG's `kanji/<5-digit hex>.svg` on jsDelivr), parsed into the same tuples and cached in `fetched`, stored in `localStorage` under `diccionari-japones-kanjivg`. While a fetch is pending the cell says "loading…"; when it finishes and the word is still selected, the stage is rebuilt. Characters that can't be found (or offline) are drawn as a placeholder labelled "no strokes". To add stroke data, take the paths from KanjiVG (CC BY-SA 3.0; keep the footer credit). Don't print or rewrite this line wholesale.
- **Groups**: `groupKit(o)` is shared by word groups (`wg`, built-ins in `WGROUPS` such as `nom` "Nouns" or `verb` "Verbs", custom ones under `diccionari-japones-grups-paraules`, form prefix `f`) and sentence groups (`sg`, `SGROUPS`, `diccionari-japones-grups`, prefix `n`). An item's `group` is a built-in key, a custom group's name, or `""` ("Other"); `of()` validates it. The form's picker (`#<p>Group`, rebuilt by `fill()`) ends with "New group…", which shows `#<p>GrpNew` to name one; while a custom group is selected, Rename (`#<p>GrpRen`, reusing the name row, `mode` is `"new"` or `"rename"`) renames it on every item, merging when the name exists, and Delete (`#<p>GrpDel`) moves its items to "Other" with an undo. `row(el, items, current)` draws the filter chips and returns the filter, reset to `"all"` when its group is gone. The callbacks (`items`, `render`, `commit`, `moved`, `hint`, `status`) tie it to each list.
- **Data model**: `words` is an array of `{id, jp, kana, romaji, ca, reg, group}` (`group` as in **Groups**, stored only when set; the `#wgroups` chips filter the list through `wGroup`, which `renderList()` applies before the search; while it is `"all"`, each grouped word gets a `.wgrp` tag after its meaning that sets the filter when clicked, coloured per group by `groupHue()` from the `--g0`…`--g7` tokens) (`ca` holds the English meaning; `kana` is the furigana reading and is optional, like `romaji`; `reg` is the optional speech register: `"hon"` honorific/敬語, `"cas"` casual/タメ口 or `""`, defined in `REG`, validated by `regOf()` and stored only when set). The register is picked in the add form (`freg` radios) and cycled from the player's badge button (`#pReg`); `regBadge()` draws an icon badge (crown for honorific, smile for casual, `REG_ICONS`) in the player and on note cards, and `regDot()` draws a coloured circle before each flagged word in the list. Their colours are the `--honor` (red) and `--casual` (blue) tokens. It is stored in `localStorage` under `KEY = "diccionari-japones-v1"` without the `id`s (`plain()`). `clean()` validates any loaded array (it requires `jp` and `ca` strings, NFC-normalizes `jp` and assigns fresh ids). Both `load()` and the backup "Load" button go through it. When storage is empty or unavailable, the app falls back to `SEED` (and `NSEED` for notes), then `seedFromRepo()` replaces them with `data/words.json` / `data/notes.json` when those can be fetched (served over http, e.g. the GitHub Pages site; not from `file://`). The `unsaved` flags keep this from overwriting anything once `save()`/`saveNotes()` has run, and the fetched data isn't stored until the first change. If you change the stored shape, bump the key or migrate it in `clean()`.
- **Ordering and search**: `sorted()` orders by accent-stripped romaji (falling back to `kana`, then `jp`) using the `"en"` locale. That default order is what `save()`/`plain()` store. The table itself follows the column sort: each header is a `.sorth` button in `#sortbar` that calls `setOrder(key)` (`kana`, `jp`, `romaji` or `ca`, defined in `ORDERS`). Clicking the active column flips the direction. `listed()` returns the words in that order, with ties keeping the default order, and `renderSortbar()` sets `aria-sort`. The state is kept in `localStorage` under `diccionari-japones-ordre`. On phones the header stays visible as a strip of sort buttons. Search matches `jp` and `kana` as raw substrings and matches romaji and English through `norm()` (NFD, diacritics removed, lowercase).
- **Stroke player**: a continuous time value `t` runs from 0 to `N` (the total strokes across every character of the word). `t` moves toward `target` in a `requestAnimationFrame` loop (`tick`). `render()` derives each stroke's `strokeDashoffset` from `t` (paths use `pathLength: 1`), and also sets the current-stroke highlight, the number visibility and the button disabled states. `prefers-reduced-motion` turns the drawing into on/off steps and disables autoplay. Each character cell that has stroke data is a `<button>` (`cells` holds `{cell, ch, from, to}`): clicking it calls `playChar(k)`, which jumps `t` to the character's first stroke and plays up to its last. `selChar` is the selected character (follows the stroke being drawn during normal playback) and is shown with `aria-pressed` on the cell and in the `#charnav` row (Prev/Next character buttons `#bPrevC`/`#bNextC` and `#charPos`, hidden for words with fewer than two drawable characters). `#bReset` is "Play from the beginning" (`restart()`).
- **Flow after mutations**: whenever `words` changes, the code calls `save()`, then `renderList(freshId?)`, then `refreshBackup()`, and calls `select(id)` when the selection should change. Deleting a word keeps a single-level undo in `lastRemoved`, offered through `status(msg, true)`. Editing reuses the add form: each row's pencil button (`.edit`) calls `startEdit(id)`, which fills the form and sets `editWordId` (`setEditing()` swaps the heading to 編集 "Edit word" and the submit to "Save") and opens the popup. Closing the popup cancels the edit (the dialog's `close` event calls `cancelEdit()`), while a half-typed new word is kept. On submit the word is updated in place with the same id and the popup closes. Deleting the word being edited or loading a backup cancels the edit (`cancelEdit()`). Don't confuse it with the notebook's own `editId`.
- **Closing the player**: the × button (`#pClose`) calls `showPlayer(false)`, which adds `.solo` to `#pDict` (one-column grid, player hidden), pauses playback and shows the toolbar's "Show stroke order" button (`#pOpen`). Clicking a row reopens it. The state is kept in `localStorage` under `diccionari-japones-reproductor`.
- **Tabs**: `showTab(name)` toggles the panels (`"dict"` or `"notes"`), pauses the player, cancels speech and remembers the tab in `localStorage` under `diccionari-japones-pestanya`. Arrow keys, Home and End move between tabs.
- **Notebook**: `notes` is an array of `{id, type, at, title, jp, kana, romaji, group, ca, reg, body, examples, strokes, grid}` (`reg` as for words, offered on grammar and sentence notes; `group` is the optional sentence group, handled by `sg` (see **Groups**), built-ins such as `aula` "Classroom instructions" or `intro` "Self-introduction"), where `type` is `gram` (grammar point: `jp` holds the structure, `examples` is `[{jp, ca}]`), `frase` (full sentence), `dibuix` (drawing) or `nota` (free note). `NFIELDS` lists which fields each type shows and keeps. It is stored under `NKEY = "diccionari-japones-apunts-v1"`, separately from the words, without ids or empty fields (`plainNotes()`), and validated by `cleanNotes()` and `noteOk()`. It falls back to `NSEED`. Cards are listed newest first (`at`). While the "Sentences" chip is selected, `renderNotes()` shows a second chip row (`#sgroups`, via `sg.row()`) that filters sentences by group (`nGroup`, reset to `"all"` when the type chip changes). Drawings are vectors, not images: each stroke is `{c: "i"|"a", w, p}`, where `p` is a flat `[x0, y0, x1, y1, …]` array in a 400×300 box and the colour is the theme's ink or accent, so drawings follow dark mode. `#nNew` and each card's edit button (`editNote()`) open the composer popup (`openComposer()`); saving closes it. The note flow mirrors the word flow: `saveNotes()`, then `renderNotes(freshId?)`, then `refreshNoteBackup()`. Deleting a note keeps a single-level undo in `lastNote`. `flash(el, msg, onUndo)` drives both status lines (`status` and `noteStatus`).
- **Auto-save to a folder**: in Chromium browsers each backup panel shows "Auto-save to folder…" (`.row.link`, `.link-pick`, `.link-stop`, `.link-msg`; hidden without `showDirectoryPicker`). The chosen directory handle is kept in IndexedDB (database `diccionari-japones`, store `kv`, key `dir`) and held in `dir`. `save()` and `saveNotes()` call `toFolder()`, which queues `writeFile()` on `dirQueue` to rewrite `words.json` / `notes.json` in the same format as the backup boxes (`wordsJson()`, `notesJson()`). After a reload the browser may need permission again; `writeFile()` asks for it on the next change (saves always follow a click). The repo's `data/` folder is the intended target.
- **Audio**: each row's speaker button (`.say`) reads the word aloud with the browser's Web Speech API (`speechSynthesis`). It speaks `kana || jp`. `loadVoices()` lists the Japanese voices in the player's `#voice` picker, ranked by `voiceScore()` so neural, Premium/Enhanced and Google voices come first. It runs again on `voiceschanged`, because browsers load voices asynchronously. The chosen voice's `voiceURI` is kept in `localStorage` under `diccionari-japones-veu`. When the browser has no speech support, the buttons aren't rendered, and the picker stays hidden when there is no Japanese voice.
- **Romaji suggestions**: typing in the add form's romaji field (`#fRo`) shows chips (`#sugg`) with the hiragana, katakana and kanji spellings. `romajiToKana(s, kata)` converts offline (Hepburn and wāpuro spellings, doubled consonants → っ, macrons → doubled vowel in hiragana and ー in katakana) and returns `""` when the input isn't valid romaji. Kanji candidates come from `kanjiFor(hira)`, which queries Google Input Tools (CORS-enabled, cached in `imeCache`, debounced) and keeps only full-length candidates written in kanji/kana. Words already in the dictionary with the same `kana` are offered too, which is all that shows offline. Picking a kanji chip fills `#fJp` and sets `#fKa` to the hiragana; picking a kana chip clears `#fKa`. The 漢字 button next to the furigana (`#fGen`) does the same from `#fKa`: it fills `#fJp` with the best kanji candidate and shows the others as chips (the Japanese field has no button of its own). It goes through `readingOf()` (accepts hiragana, katakana or romaji; katakana is turned into hiragana by `toHira()`) and `fillKanji()`.
- **Sentence generation**: the sentence fields (`#nJp`, `#nKa`, `#nRo`, `#nCa`) are one-row `textarea.line`s that grow with each line break (`field-sizing: content`; two rows and a resize handle where unsupported), and cards show the breaks (`white-space: pre-line`). In the notebook's "Sentence" form, the `#nGen` button ("Generate") next to the romaji field fills `#nKa` with `phraseToKana()` and `#nJp` with Google's best conversion (`imeLookup()`, shared with `kanjiFor()`). `phraseToKana()` converts word by word, spelling standalone `wa`/`o`/`e` as the particles は/を/へ and a few fixed words (`FIXED`, e.g. こんにちは); `.,?!` become 。、？！. Both converters work line by line and keep the breaks (`phraseToKana()` → `lineToKana()`, `imeLines()`). Offline, `#nJp` keeps the hiragana and `noteHint()` says so. The 漢字 button next to the sentence's furigana (`#nKan`) fills `#nJp` from `#nKa` with `imeLookup()`.
